# 消息

## 消息格式

### 调用发送

```json
{
    "操作ID":"UUID",
    "操作目标":"目标UUID",
    "操作":"调用",
    "参数":{"option":"write","unprotected":true} #目标是
}
```
(待定)网页按收到的顺序执行，发出回复之后才执行下一条
谁发出调用，谁生成操作ID

可用操作及其参数:
* 调用
    **kargs
* 写入属性
    key:str
    value:Any
* 读取属性
    key:str
* 解除引用(为GC预留)
    uuid:UUID

目标ID保留全0与全1留给内部使用

### 调用结果回复
基本回复格式:
```json
{
    "操作ID":"UUID",
    "执行成功":true,
    "类型":"boolean",
    "值":true
}
```

可用类型:(number的特殊值直接传,无需值字段)
* object #function并入
* undefined
* null
* string
* boolean
* symbol
* object
* bigint #int
* number #float
* nan
* infinity
* -infinity
* -0

值字段,在成功时为返回结果,失败时则为错误数据(消息或分析用对象)

## 握手

1.浏览器请求网页
2.服务端返回包含脚本+握手UUID的网页
3.脚本执行,携带uuid再次请求相同端点建立ws通道
4.启动该连接,服务端根据发来的uuid创建或复用window对象,并调用路由的函数处理window

## 对象表
每端维护这些表:
对方引用己方的对象:{uuid:对象}
{对象:{内部数据...}}(对象弱引用)
